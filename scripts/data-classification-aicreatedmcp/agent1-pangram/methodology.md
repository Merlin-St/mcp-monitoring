# Agent 1: AI Text Detection via Pangram API and Heuristic Fingerprinting

## Objective

Estimate the proportion of MCP (Model Context Protocol) servers whose README documentation was substantially generated by AI, using text-level AI detection approaches.

## Detection Methods (Priority Order)

### Method 1: Pangram Labs API (Primary)

**Tool**: Pangram v3 REST API (with optional `pangram-sdk` Python package)

**Approach**: Pangram is a transformer-based neural network trained to distinguish text written by large language models from text written by humans. It provides document-level and window-level classifications. The v3 API returns three fractions (`fraction_ai`, `fraction_ai_assisted`, `fraction_human`) that sum to 1.0, along with a headline classification, prediction explanation, and per-window labels with confidence scores.

**API Details** (verified against actual Pangram documentation):
- **Endpoint**: `POST https://text.api.pangramlabs.com/v3`
- **Authentication**: `x-api-key` header (NOT Bearer token)
- **Request body**: `{"text": "<readme content>"}`
- **V3 response fields**:
  - `headline`: Summary classification ("Fully Human Written", "AI Assisted", "Fully AI Generated")
  - `prediction`: Detailed explanation of the classification
  - `fraction_ai`: Fraction of document classified as AI-generated
  - `fraction_ai_assisted`: Fraction classified as AI-assisted
  - `fraction_human`: Fraction classified as human-written
  - `windows`: List of text segments with per-window `label`, `ai_assistance_score`, `confidence`, `word_count`

**Composite AI probability formula**:
```
ai_prob = fraction_ai + 0.5 * fraction_ai_assisted
```
This weights fully AI-generated content at 1.0 and AI-assisted content at 0.5, reflecting that AI-assisted text involves human editing.

**Key capabilities**:
- Detects content from ChatGPT, Claude, Gemini, Llama, Perplexity
- 99.98%+ reported accuracy with 1-in-10,000 false positive rate
- Three-way classification: human / AI-assisted / AI-generated (not just binary)
- Sliding window analysis for long documents
- Window-level labels: "Human", "Lightly AI-assisted", "Moderately AI-assisted", "Heavily AI-assisted", "AI Generated"

**Requirements**:
- `pip install pangram-sdk` (optional; script also supports direct REST API via `requests`)
- `pangram_key` environment variable (lowercase; free researcher keys at https://pangram.com)
- Internet access for API calls

**Cost**: Developer plan starts at $100/month for 2,000 API credits. Researcher keys available for free for non-commercial research. One credit per ~400 words analyzed.

**Rate limiting**: 0.6 second delay between requests. Intermittent 502 errors occur and are handled via exponential backoff retry (up to 5 retries).

**Script**: `pangram_detect.py`

**Documentation**:
- REST API docs: https://pangram.readthedocs.io/en/stable/api/rest.html
- V3 migration guide: https://www.pangram.com/blog/v3-api-migration-guide
- Python SDK: https://github.com/pangramlabs/pangram-sdk
- Technical report: arXiv 2402.14873

### Method 2: Binoculars (ML Fallback)

**Tool**: Binoculars (ICML 2024, arXiv 2401.12070)

**Approach**: Zero-shot detection using perplexity ratios between two closely related language models (Falcon-7B and Falcon-7B-Instruct). The core insight is that machine-generated text has lower cross-perplexity between related models compared to human-written text.

**Key capabilities**:
- Zero-shot (no training data needed)
- Detects 90%+ of ChatGPT and other LLM output at 0.01% FPR
- Model-agnostic detection (same detector works for multiple LLMs)
- No API key required

**Requirements**:
- `pip install binoculars torch transformers accelerate`
- GPU with >= 16GB VRAM (strongly recommended)
- ~14GB disk space for model weights (Falcon-7B x2)
- CPU mode available but impractically slow (~2-5 min per sample)

**Script**: `binoculars_detect.py`

### Method 3: Heuristic Fingerprint Detection (Always-Available Fallback)

**Approach**: Multi-signal heuristic analysis combining 8 independent detection signals. This method requires zero dependencies beyond the Python standard library and runs in ~2 seconds for all 500 servers.

**Script**: `detect_heuristic.py`

#### Detection Signals

| Signal | Weight | Description |
|--------|--------|-------------|
| Lexical fingerprints | 0.25 | Matches against ~80 known AI-overused phrases and words (e.g., "delve into", "comprehensive solution", "seamlessly integrates") |
| AI attribution | 0.20 | Explicit claims that README/code was generated by AI (NOT general tool mentions) |
| Burstiness | 0.15 | Sentence length variance; AI text is more uniform than human writing |
| Structural patterns | 0.10 | Standardized heading conventions typical of AI-generated READMEs |
| Formulaic opening | 0.10 | Stereotypical AI opening patterns ("A powerful and comprehensive...") |
| Hedging language | 0.10 | Density of hedge phrases ("it's important to note", "keep in mind") |
| Prose-to-code ratio | 0.05 | AI READMEs tend to be prose-heavy relative to code examples |
| Emoji formatting | 0.05 | Emoji section headings (common in readme-ai and AI-generated docs) |

#### Composite Score Calculation

Individual signal scores (each in [0, 1]) are combined via weighted average, then passed through a sigmoid calibration function to produce a final probability:

```
raw_composite = sum(signal_score * weight) / sum(weights)
calibrated = 1 / (1 + exp(-6 * (raw_composite - 0.45)))
```

The sigmoid centers at 0.45 with steepness 6, pushing scores toward the extremes (more bimodal distribution).

#### Classification Thresholds

| Probability | Classification |
|-------------|---------------|
| >= 0.70 | Likely AI-generated |
| 0.40 - 0.69 | Mixed or uncertain |
| < 0.40 | Likely human-written |

#### MCP-Specific Adaptations

A critical design decision was required for the AI attribution signal. MCP server READMEs routinely mention "Claude", "Cursor", "Copilot", "Windsurf" as **supported MCP clients** (since Claude Desktop is the primary MCP host). These mentions do NOT indicate AI authorship.

The attribution detector was specifically tuned to fire only on explicit authorship claims:
- STRONG: "This README was generated by ChatGPT", "Built entirely with Claude Code", "vibe coded"
- WEAK: "AI-assisted development", "Made with Claude"
- IGNORED: "Configure Claude Desktop", "Works with Cursor", "GitHub Copilot integration"

## Pipeline Orchestration

The `run_detection.py` script runs methods in priority order:

1. Heuristic detection always runs first (fast, reliable baseline)
2. If `PANGRAM_API_KEY` is set: run Pangram API
3. If GPU + binoculars installed: run Binoculars
4. Merge all available results into `merged_results.json`

When multiple methods are available, the ensemble score is:
```
ensemble = 0.7 * ml_score + 0.3 * heuristic_score
```

Partial AI assistance in README writing appears less common.

**Key finding**: Approximately **50% of MCP server READMEs** in the sample have AI-generated content, according to Pangram's trained classifier. This is dramatically higher than the heuristic estimate of 0.2%, demonstrating the limitations of rule-based detection for modern AI text.

## Interpretation and Limitations

### Heuristic vs. Pangram detection rates

The heuristic method's 0.2% "likely AI-generated" rate is a **strict lower bound**. The Pangram trained classifier captures subtle statistical patterns invisible to lexical heuristics, producing substantially higher detection rates that better reflect the true proportion of AI-generated README content.

Key reasons the heuristic rate is low:

1. **READMEs are short functional documents**: Unlike essays, developer READMEs are template-driven even when human-written. This reduces the discriminative power of style-based signals.

2. **MCP servers follow a common structure**: Features, Installation, Usage, Configuration sections are standard for ANY MCP server, human or AI-written.

3. **Modern AI writes convincingly**: Post-2024 LLMs produce text that closely mimics experienced developer writing. Simple lexical heuristics catch only the most stereotypical cases.

4. **Code was AI-generated but README may not be**: A server can be fully AI-coded while its README was human-written (or vice versa).

5. **The heuristic is deliberately conservative**: High precision is prioritized over recall. The sigmoid calibration pushes most scores below 0.20, meaning only servers with multiple strong signals are flagged.

### README vs. code detection

This analysis detects AI-generated **README text** as a proxy for AI-created servers. This is an imperfect proxy because:
- AI tools (readme-ai, ChatGPT) can generate READMEs for human-written code
- Human developers may edit AI-generated READMEs, removing detectable signals
- AI-coded servers may have human-written or minimal READMEs

For more comprehensive detection, this should be combined with:
- Agent 2: Git commit message pattern analysis
- Agent 3: Code pattern analysis
- Agent 4: Repository structure analysis

## Replicability

### Quick start (heuristic only, no API key needed)

```bash
source ~/mcp-monitoring/.venv/bin/activate
cd scripts/data-classification-aicreatedmcp/agent1-pangram
python run_detection.py --method heuristic
```

Output: `data/external-aicreatedmcp/agent1-pangram/merged_results.json`

### With Pangram API

```bash
# Get API key from https://pangram.com (free for researchers)
# The script reads from env var 'pangram_key' (lowercase) or ~/.pangram_key file
pip install pangram-sdk  # optional; REST fallback available without SDK

source ~/mcp-monitoring/.venv/bin/activate

# Option 1: Run standalone Pangram detection
pangram_key=your_key_here uv run python3 scripts/data-classification-aicreatedmcp/agent1-pangram/pangram_detect.py

# Option 2: Run via orchestrator (also runs heuristic and merges)
pangram_key=your_key_here uv run python3 scripts/data-classification-aicreatedmcp/agent1-pangram/run_detection.py --method pangram
# Or auto-detect:
pangram_key=your_key_here uv run python3 scripts/data-classification-aicreatedmcp/agent1-pangram/run_detection.py
```
